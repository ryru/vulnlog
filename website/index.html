How Vulnlog works

Scanners, customers, and auditors report vulnerabilities in your software. Many don't affect it, and the others take time to fix. Vulnlog is where you keep your answer.

The Vulnlog file

A YAML file in your Git repository. Each vulnerability is one entry. It says which releases are affected, your verdict, the analysis behind it, and what you plan to do.

The Vulnlog tools

A command-line tool, a Gradle plugin, and a GitHub Action. They check the Vulnlog file and generate from it what your scanners, your team, and your customers need.

What Vulnlog generates

Suppression files

Your scanners stop reporting what you've already analysed. Vulnlog writes the native format for Trivy, Snyk, OWASP Dependency-Check, and cargo-audit, and a generic JSON file for every other scanner.

Impact report

One HTML file that shows which releases a vulnerability affects, and how severely. Share it with your customers, auditors, and managers.

OpenVEX documents

OpenVEX documents tell your customers' tools whether a release is affected by a vulnerability. The feature is incubating, and CycloneDX VEX follows soon.

One entry in, several files out

An entry from Acme Shop, the example project of the documentation, and what three commands generate from it.

Your Vulnlog file acme-shop.vl.yaml, one entry

- id: CVE-2022-22965
  name: Spring4Shell
  description: Remote code execution through data binding in Spring Framework
  releases:
    - 4.2.0
    - 4.3.0
  packages: ["pkg:maven/org.springframework/spring-beans@5.3.15"]
  reports:
    - reporter: trivy
      at: 2026-04-07
      suppress:
        expires_at: 2027-03-31
  tags:
    - backend
    - container
  analysis: >-
    Acme Shop runs as a Spring Boot executable JAR on JDK 17. The published
    exploit needs a WAR deployment on Apache Tomcat, but Spring advises all
    users to upgrade.
  analyzed_at: 2026-04-08
  verdict: affected
  severity: medium
  disposition: will fix
  comment: Planned for 4.4.0 together with the Spring Boot update.

Why a file in your repository

No server, no account

Vulnlog is a YAML file and tools you run from the command line, in Docker, with Gradle, or in GitHub Actions.

Reviewed like code

You change an analysis in a pull request. Git shows what changed, who changed it, and when.

Independent of your scanner

Vulnlog doesn't scan. It works alongside the scanners you have, and stays when you switch.

Vulnlog uses Vulnlog

These files are about Vulnlog itself. Vulnlog generates them from the Vulnlog file of the project.

Install Vulnlog

Install script, on Linux and macOS
curl -fsSL vulnlog.dev/install | sh
Homebrew, on macOS
brew install vulnlog/vulnlog/vulnlog
Docker
docker pull ghcr.io/vulnlog/vulnlog:VULNLOG_VERSION
GitHub Actions
- name: Set up Vulnlog CLI
  uses: vulnlog/setup-vulnlog@v1
  with:
    version: VULNLOG_VERSION
Gradle plugin, in build.gradle.kts
plugins {
    id("dev.vulnlog.plugin") version "VULNLOG_VERSION"
}
